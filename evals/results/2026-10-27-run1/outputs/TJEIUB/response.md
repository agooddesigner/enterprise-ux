# UX audit: Vendor Invoices (Acme Ops Console)

**Scope:** one screen, the HTML you pasted, and one generic user role. The standard is WCAG 2.2 AA. This is a single reviewer working from the source only. I haven't run it, so I haven't done a screen-reader or keyboard pass or an automated scan.

**Summary:** This isn't ready to ship. Three things could cause data loss or block the page: Delete All fires with no confirmation, the loader overlay never goes away, and the Submit handler wipes the form. Keyboard users can't open an invoice at all, because the rows are clickable divs. Focus outlines are removed with no replacement, so keyboard users can't see where they are. Error handling is mostly missing.

## Findings, ranked

| # | Sev | Location | Problem | Why it matters | Fix |
|---|---|---|---|---|---|
| 1 | 4 | **Delete All** button | `deleteAll()` fires a DELETE on the whole collection on one click. There's no confirmation, no count, no undo, no result message and no UI update. It's a plain unstyled button, and it's reachable by an accidental click or an Enter keypress. | Irreversible loss of all invoices (Nielsen #3, #5, #9). | Move it into a bulk "⋯" menu and make it act on selected rows. Use soft delete with Undo, or a typed confirmation: "Delete all 2 invoices? This can't be undone. Type DELETE." Disable it for roles without permission, and say who can do it. |
| 2 | 4 | `#loader` | A `position:fixed; inset:0` overlay with "Loading..." and nothing that ever removes it. It sits over the whole page, so it blocks pointer clicks on everything below it. | The core task is impossible (3 → 4 if it ships). | Remove it on load. Replace it with a skeleton or an inline `role="status"` indicator that doesn't intercept input. |
| 3 | 4 | Submit handler | Clicking Submit clears every input whether or not anything was saved, and nothing is sent. The button is also `disabled` with no way to enable it. The code comment claims "on any form error the form is reset." | The user loses their input and nothing is saved. Violates "never lose user input" (Nielsen #5, #9). | Keep the values on failure. Only clear the form after a confirmed success. Enable the button by default, validate on submit, and prevent double-submit. |
| 4 | 4 | Invoice rows | Rows are `<div onclick>`, so they have no role, no tabindex and no key handler. Keyboard and screen-reader users can't open an invoice (WCAG 2.1.1, 4.1.2). The Save and Delete buttons sit inside the row and don't call `stopPropagation()`, so every click on them also opens the modal. | Core task blocked for keyboard users. Mouse users get an unwanted modal on every action. | Make the ID or vendor name a real `<a href="/invoices/1">` or button. Drop the row-level `onclick`, or at minimum stop propagation on the row buttons. |
| 5 | 4 | Global CSS | `button:focus, input:focus, a:focus { outline:none }` with no replacement. | No visible focus anywhere (WCAG 2.4.7, 2.4.13). Keyboard users are lost. | Delete the rule. Use `:focus-visible` with a 2px outline at 3:1 contrast. |
| 6 | 3 | Save/Delete icon buttons | These are 16×16px emoji buttons with no accessible name (WCAG 4.1.2, 2.5.8 target size). Delete sits right beside Save, and the Delete click does nothing visible. | Screen readers announce "button". A mis-click deletes data (Fitts's Law). | Use `aria-label="Delete invoice 8f3a-22c1"` and a minimum 24px target, ideally 32px with spacing. Put Delete in a "⋯" menu with a confirmation or Undo. Replace emoji with an SVG icon set. |
| 7 | 3 | Row actions (`save`/`del`) | `fetch` has no `.ok` check, so a 4xx or 5xx is treated as success. `del` gives no feedback and doesn't update the UI. `save` has no payload, no pending state and no success message. The `.catch` only fires on a network failure, but the toast says "Error 500". | Users can't tell what happened (Nielsen #1, #9). | Check `res.ok`. Show a pending state, then update the row. Show errors with a reason and a retry. Use Undo for delete. |
| 8 | 3 | Toast | It disappears after 2s and is unstyled. It has no `role="status"` or `aria-live`, so screen readers never hear it (WCAG 4.1.3, 2.2.1). The copy is "Error 500: Something went wrong". | Errors are missed, and the text isn't actionable. | Use a persistent inline or banner error for failures, with `role="alert"`. Say what failed and how to fix it: "Couldn't save invoice 8f3a-22c1. Check your connection and try again." |
| 9 | 3 | Form | Placeholders are the only labels, so the label disappears once you type (WCAG 3.3.2, 1.3.1). "Invalid input" is permanently visible, doesn't name a field, and isn't linked with `aria-describedby` or announced. It relies on red colour alone. Amount is `type=text` with no `inputmode` or format hint, and the button label "Submit" is vague. | Users can't tell what is wrong, and screen readers can't either. | Add visible `<label>`s. Show the error only after a failed validation, next to the field, with `aria-invalid` and `aria-describedby`. Add an error summary and move focus to it. Use `inputmode="decimal"` and a clear label such as "Add invoice". |
| 10 | 3 | Status column | Status is a coloured ● with no text, so it fails WCAG 1.4.1 for colour-blind and screen-reader users. `#2e9e44` on white is about 3.4:1, which fails the 4.5:1 text threshold. | Users can't tell paid from overdue, or whatever the two states mean. | Use a text badge ("Paid" / "Overdue") plus an icon. Check each colour pair at 4.5:1. |
| 11 | 3 | Grid | `.grid` and `.row` have no CSS, so the columns won't line up. It's built from divs with no table semantics (WCAG 1.3.1), and the header row is only styled visually. Amounts use a `.num` class on spans, but the only rule is `td.num`, so they're not aligned. | The data is unreadable for screen readers, and the layout is likely broken. | Use a real `<table>` with `<th scope>`, a caption and a right-aligned amounts column. Show consistent decimals and a currency, for example "1,200.50 USD". |
| 12 | 3 | Vendor column | The long Globex name has no truncation or wrap rule, and no tooltip. | It breaks the layout at narrow widths (reflow, WCAG 1.4.10). | Truncate with an ellipsis and a title or tooltip. Allow wrapping in a detail view. |
| 13 | 3 | Modals | `openInvoice` calls `showModal`, and a Confirm button then opens a second modal on top. There's no mention of focus trap, Esc or focus return (WCAG 2.4.3). `location.hash = ''` also clears URL state, so the open record isn't linkable and Back doesn't work. | Users are disoriented in a nested modal and can't share a link. | Use a detail page or side panel with a URL like `/invoices/1`. Allow one dialog at a time. Trap focus and return it on close. |
| 14 | 3 | Page states | There's no empty state, no loading state for the table, no error state for load failure, no pagination, no search or filter, and no sort. "Showing all invoices" gives no count. | It doesn't scale beyond a couple of rows, and "all" is a lie when a load fails (Nielsen #1; state matrix). | Add states for first-use empty, no results, loading, error and no permission. Add pagination, search, sort and a result count. |
| 15 | 3 | `.muted` text | `#b5b5b5` on white is about 2.1:1. | Fails WCAG 1.4.3. | Use `#6b6b6b` or darker (4.5:1 or better). |
| 16 | 2 | Document | There's no doctype, no `lang`, no viewport meta, and the title is just "App". There's no `<main>` or `<nav>` landmark, and the page title "Acme Ops Console" is a `<b>`, not a heading. The section heading is an `<h2>` with no `<h1>`. There's also a stray `down. -->` at the top. | Fails WCAG 3.1.1, 2.4.2 and 1.3.1. It renders in quirks mode and doesn't scale on mobile. | Add `<!doctype html>`, `<html lang="en">`, a viewport meta tag, a descriptive title, landmarks and a single `<h1>`. Remove the stray text. |
| 17 | 2 | Sticky header | The 72px sticky header can cover a focused element when tabbing (WCAG 2.4.11). | A keyboard user can lose sight of focus. | Add `scroll-padding-top: 80px` on `html`. |
| 18 | 2 | Admin context | The screen doesn't show the org or environment, the user's role, or any audit trail for deletes. IDs are raw hashes, and there are no dates. | Higher risk in an admin console with destructive actions. | Show the org and environment. Add due and created dates with timezones, and an activity log. |

## Accessibility summary (WCAG 2.2 AA)

These criteria fail: 1.3.1, 1.4.1, 1.4.3, 1.4.10 (likely), 2.1.1, 2.4.2, 2.4.3, 2.4.7, 2.4.11 (likely), 2.5.8, 3.1.1, 3.3.1, 3.3.2, 4.1.2 and 4.1.3. I haven't done a screen-reader or keyboard run, and an automated scan on its own wouldn't catch most of these.

## What works

- Using `sticky` for the header is reasonable.
- The table intent is clear: ID, vendor, amount and status are the right columns.

## Fix order

1. Items 1–5: confirm and undo for delete, the loader, the form reset, keyboard access to rows, and focus outlines.
2. Items 6–10: icon button names and sizes, real feedback from the API calls, labels and errors, and text status.
3. Items 11–18: table semantics, states, document basics and context.

Before launch, test with about 5 users per role who handle invoices, covering "find an invoice, fix it, delete one by mistake and recover".
